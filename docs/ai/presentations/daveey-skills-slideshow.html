I ♥ Skills

A toolkit for autonomous code authoring & review
16 composable skills that handle everything from running tests to fixing entire PR stacks — from the core loop through orchestration to skill management.
Part 1

The Core Loop

Test, clean, submit. The foundation every other skill builds on.
Testing t.run-tests
Run tests progressively with fast feedback loops
Progressive test runner: starts with the fastest feedback (known failures from context), expands to pytest, then full CI. Stops at first failure to fix incrementally.
Flow
Failed from context → pytest --changed → metta ci

Key Details

  • Step 1: Re-run specific tests from error messages in conversation
  • Step 2: Run pytest on changed files
  • Step 3: Full CI validation (lint + types + tests)
  • Stops at first failure — fix then re-run
Graphite pr.cool
Clean Out Old Leftovers — remove backwards compat cruft
Two-phase cleanup: first verifies the branch scope matches its PR description, then hunts and removes backwards-compatibility patterns — aliases, defensive fallbacks, and shims.
Flow
Worktree → Verify scope → Find compat → Fix each → Test → Submit

Patterns Removed

  • OldName = NewName → update callsites, delete alias
  • x or default → assert x, use directly
  • getattr(o, "a", d) → o.a directly
  • dict.get(k, d) → dict[k] directly
  • Wrapper shims → inline at callsites
Graphite pr.submit
The full submit pipeline — clean, test, submit, verify
The workhorse skill. Runs /pr.cool, checks for disabled tests, lints, commits, submits to Graphite (starting CI), then runs tests locally in parallel. Fixes and re-submits if tests fail.
Flow
/pr.cool → Disabled tests → Lint → Commit → Submit → Test (parallel w/ CI)

Why Submit Before Testing?

  • CI starts immediately — no waiting for local tests
  • Local tests and CI run in parallel
  • If local tests fail, fix and re-submit
  • Net time savings on branches likely to pass
Part 2

The Fix Pipeline

Reactive skills that diagnose and fix problems — from individual comments up to entire stacks.
Graphite pr.fix-comments
Address PR review comments with regression tests
For each unresolved review thread: reads the full conversation, classifies the issue (behavioral vs style), writes a regression test that fails, makes the fix, verifies the test passes, replies, and resolves.
Flow per comment
Understand → Classify → Write test → Verify fails → Fix code → Verify passes → Resolve

Comment Classification

  • Behavioral bug → write test, then fix
  • Edge case → write test, then fix
  • Style/naming → fix directly
  • Documentation → fix directly
  • Design disagreement → ask user
Graphite pr.fix-ci
Find and fix CI failures on a branch
Fetches CI status using commit SHA (never gh pr checks — it returns stale data), downloads failure logs, classifies the failure type, fixes, verifies locally, and submits the update.
Flow
Worktree → Check CI (SHA) → Get logs → Analyze → Fix → Verify → /pr.submit

Failure Classification

  • Test failures → fix test or code
  • Lint errors → metta lint
  • Type errors → fix annotations
  • Build errors → fix imports/deps
  • Timeout → optimize or increase limit
Orchestration pr.fix-branch
Full branch fix — sync, restack, comments, CI, submit
Orchestrates the complete fix cycle for a single branch. Dispatches three sub-agents for the heavy lifting (fix-comments, fix-ci, submit), keeping the orchestrator lightweight.
Architecture
fix-branch (orchestrator)
↓
sync + restack
↓
Sub: fix-comments
→
Sub: fix-ci
→
Sub: submit

Why Sub-Agents?

  • Each step reads lots of logs/comments
  • Multiple fix-verify cycles per step
  • Significant context accumulation
  • Sub-agents start fresh — no context overflow
  • Failed sub-agents can be retried independently
Orchestration st.fix-stack
Fix an entire stack — sub-agent per branch, bottom-up
Parses the entire Graphite stack, orders branches bottom-up, then dispatches a pr.fix-branch sub-agent for each. Sequential — lower branches must complete first.
Architecture
fix-stack (orchestrator)
↓ sequential
fix-branch (branch-1)
↓
fix-branch (branch-2)
↓
fix-branch (branch-N)

Key Details

  • Each branch gets its own worktree
  • Lower branches affect upper → sequential
  • Each branch submitted immediately after fixing
  • Orchestrator tracks success/failure per branch
  • No risk of context limits on large stacks
Part 3

Branch Manipulation

Restructure branches — route changes, split, extract, and stack for optimal reviewability.
Graphite st.apply
Route uncommitted changes to the correct stack branches
When you have uncommitted changes that belong to different branches in your stack, this skill analyzes, groups, and routes each change to its correct branch using stash/patch/checkout workflows.
Flow
Analyze changes → Identify targets → Group by branch → Confirm → Apply each → Verify

Routing Patterns

  • Single file → different branch
  • Mixed hunks in one file → git add -p
  • Accidental changes on wrong branch
  • Creates new branches for unrelated changes
Graphite st.split
Split a branch into sequential branches in-place
Splits one branch into multiple sequential branches occupying the same stack position. Preserves the stack: upstack branches are restacked onto the new top, and the original PR is closed.
Example: splitting c into x, y
a → b → c → d
becomes
a → b → x → y → d

Key Details

  • Records parent and upstack branches first
  • Creates new branches from parent
  • Restacks upstack onto new top
  • Closes original PR with cross-references
  • Runs /pr.submit for each new branch
Graphite st.extract + st.extract-copy
Pull features out of a branch into new parallel branches
Two flavors of extraction. extract moves changes out (destructive — original is modified). extract-copy copies changes out (original unchanged, for early landing). Both review code quality and tests before acting.
Shared Flow
Analyze → Identify feature → Review & improve → Create branch → Move / Copy → Test & submit

extract vs extract-copy

  • extract: original modified (feature removed)
  • extract-copy: original unchanged
  • extract: clean separation, no overlap
  • extract-copy: branches overlap, git reconciles later
  • Both: review code quality + tests before acting

Shared Dependencies

  • Small (<50 lines): duplicate in both branches
  • Significant: extract to foundation branch first
  • Will diverge: accept merge conflict later
Graphite st.make-stack
Break a large branch into a reviewable Graphite stack
Analyzes a large branch, groups changes into logical ~200-400 line chunks with proper dependency ordering, gets user approval, then creates/tests/submits each branch. Restacks upstack branches afterward.
Flow
Analyze + stack position → Group logically → Propose → Approve → Create each → Restack upstack

Grouping Principles

  • Dependencies first (infra before features)
  • One concern per branch
  • Tests with implementation
  • ~200-400 lines per branch
  • Each branch must pass tests independently
Part 4

Persistence

The meta-skill that wraps any other skill in a retry loop until it succeeds.
Control Flow cf.really
Run any skill until it succeeds — the persistence layer
Meta-skill that wraps any other skill in a retry loop. Determines success criteria from the skill's domain, handles async waits (CI polling), tracks progress across iterations, and only gives up when truly stuck.
Flow
Determine success → Run skill → Wait for async → Check success ↺

When to Stop

  • Keep going: fewer failures than last time
  • Keep going: different failures (peeling the onion)
  • Keep going: first time seeing this failure
  • Stop: exact same failures 3x in a row
  • Stop: failures increasing for 3+ iterations
  • Stop: infrastructure issue (not a code problem)
Part 5

Skill Management

Skills for creating, submitting, syncing, and updating other skills.
Meta sk.make-skill
Create a new skill with quality review and submission
Full skill authoring workflow. Gathers intent, scans existing skills for composition opportunities, writes the skill, reviews against a quality checklist, sets up files and symlinks, then submits.
Flow
Gather intent → Scan related → Write → Review → Setup → /sk.submit-skill

Quality Checklist

  • Description = triggering conditions only
  • Concrete bash/code, not pseudocode
  • Integration section (uses/called-by/pairs)
  • Quick Reference table for scanning
  • Under 500 words for most skills
Meta sk.submit-skill
Commit, submit, publish, and merge skill changes
The submission pipeline for skills. Creates a worktree, lints, commits to Graphite, enables merge-when-ready, then monitors the PR — running /pr.fix-branch if CI fails or review comments appear.
Flow
Worktree → Lint → Commit → Submit → Publish → Monitor

Key Details

  • Lint is mandatory — never skipped
  • Enables GitHub auto-merge via gh pr merge --auto
  • Polls every 30s until merged
  • Auto-runs /pr.fix-branch if issues appear
Meta sk.sync-skills
Symlink skills to Claude Code and Codex
The simplest skill. Takes a directory of skills and creates symlinks so Claude Code and Codex can discover them. Run after switching worktrees or repos.
Flow
Resolve dir → Symlink each → Report

Key Details

  • Targets: ~/.claude/skills/ and ~/.codex/skills/
  • Finds dirs containing SKILL.md
  • Creates symlinks (not copies)
  • Restart session for new skills to appear
Meta sk.update-skill
Apply changes to an existing skill and submit
Lightweight wrapper: locate a skill, apply the requested edits, then hand off to sk.submit-skill for the commit/submit/publish flow.
Flow
Locate SKILL.md → Apply changes → /sk.submit-skill

Key Details

  • Preserves existing structure unless asked otherwise
  • Updates Integration section if deps changed
  • Keeps skills under 500 words
  • Delegates all git/submit work to sk.submit-skill
